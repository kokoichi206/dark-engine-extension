# テストの目的と残す基準

このリポジトリでは、ビルドした Chrome 拡張の注入・表示・設定保存をブラウザテストで確認し、色の性質とドメイン境界を単体テストで確認します。外部サイトの DOM に依存しない回帰テストを、このリポジトリ内に置きます。

テストは、実際に壊れ得る利用者の操作・表示・互換性に結び付くものを残します。内部関数の呼び出し回数、スタイルシートの構造、実装から転記した変換結果だけでは合格にしません。正常な実装変更でも失敗する書式・並び順の固定は避けます。

## 単体テストが保証すること

| 対象         | 確認する性質                                                    | 検知できる不具合の例                                |
| ------------ | --------------------------------------------------------------- | --------------------------------------------------- |
| 明るい面     | 白・薄い赤・薄い青を暗くする                                    | 背景変換の脱落、背景と文字の役割の取り違え          |
| 既存の暗い面 | 黒や暗いグレー・青を変色させない                                | 反転による明色化、繰り返し変換による変色            |
| 透明度       | 元の alpha を維持する                                           | 透明・半透明の要素の不透明化                        |
| 有彩色       | 赤・緑・青の違いを残し、有限な RGB 色域に収める                 | 全色の無彩色化、色の取り違え、NaN や色域外の出力    |
| 本文色       | 不透明な文字と単色背景のコントラスト                            | 明度調整の欠落、コントラスト判定の不備              |
| ドメイン入力 | 正規化、重複除去、IDN / IP の保存、空欄での解除、無効入力の拒否 | 意図しない除外範囲への拡大、設定の破損              |
| ドメイン照合 | 自身・子孫だけを対象にし、親・兄弟・似た別名を含めない          | `notexample.com` の巻き込み、サブドメインの除外漏れ |

配色の検証では、代表的な明るい背景の相対輝度が `0.1` 未満であることを、この拡張の品質基準にしています。特定のパレットや変換係数を固定するための数値ではありません。本文色は [WCAG 2.2 のコントラスト比](https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio) に従って `4.5 : 1` 以上を判定します。

低レベルの計算でも、半透明の赤と青の混色、透明・不透明な前景の合成は、[W3C の合成規則](https://www.w3.org/TR/compositing-1/#simplealphacompositing) と既知の結果で判定できるため単体テストを残します。単に関数が短いことや、固定値の期待値を持つことだけでは削除しません。

色の判定は [visual-contract.ts](../tests/support/visual-contract.ts) で行います。このファイルは本番の `luminance`、`contrast`、`composite`、再マップ関数を参照せず、規格の式から判定します。同じ本番コードの誤りで、変換と合否判定が同時に誤ることを防ぎます。ここでの合格は、画像上の文字や全サイトの WCAG 適合を保証するものではありません。

## ブラウザテストが保証すること

[tests/browser](../tests/browser) に Playwright のテストがあります。`dist` の Manifest とスクリプトを一時プロファイルの Chromium に読み込み、拡張 API をモックせず実行します。

| 対象                 | 利用者側で確認する結果                                                                                                                                            |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 通常ページ           | 本文・リンク・フォーム・疑似要素・Shadow DOM・iframe / srcdoc・SVG が暗い面で読める                                                                               |
| 動的な追加・変更     | 非同期で追加された要素と、後から変わった inline style の配色が追従する                                                                                            |
| CSSOM / hover        | 新しい CSS ルールと hover を取り込み、背景だけでなく文字も読める                                                                                                  |
| グラデーション / URL | グラデーションを残して色を暗くし、背景画像の URL を壊さない                                                                                                       |
| 全体の ON/OFF        | ポップアップで保存・再読み込みでき、新しいタブにも保存状態が反映される                                                                                            |
| 画像                 | 拡張の ON/OFF で画面上の画像の色を変えない。画像自身と祖先のフィルターの両方が判定対象                                                                            |
| CSP / 色形式         | `script-src 'none'` / `style-src 'self'` と OKLCH / Display P3 を使うページでも読める                                                                             |
| 設定の保存・入力拒否 | 保存後の再表示と実ページへの反映を確認。不正入力で既存設定を破壊しない                                                                                            |
| 現在のドメインの除外 | ポップアップで追加し、設定画面を開いて解除し、元の表示へ戻れる                                                                                                    |
| 設定同士の独立性     | 除外一覧の変更や解除で、全体の OFF を勝手に ON にしない                                                                                                           |
| Sheets 向けの描画    | セル内部の背景ピクセルが暗く、文字のピクセルが明るい。対象外の Canvas は変えない                                                                                  |
| Canvas API の互換性  | `fillRect`、`fill`、`stroke`、`strokeRect`、`fillText`、`strokeText` と overload が実際に描画する。`maxWidth` と呼び出し直後の `fillStyle` / `strokeStyle` を保つ |
| Sheets の除外        | 除外・再読み込みで本文とセルが元へ戻り、解除後は再び暗い表示で読める                                                                                              |

画像は、要素自身の `filter` 値ではなく、画面のスクリーンショットをブラウザでデコードした色で判定します。PNG の圧縮結果や画像端のサブピクセル描画差は比較しません。遅延 DOM 追加の検証では、初期ロードの再走査が終わった後で、クリック時の再走査より遅い非同期更新を起こします。初期化や入力イベントが更新を偶然拾って合格することを避けます。

Sheets 用のブラウザテストは、Sheets の URL へ制御した HTML をルーティングして実行します。MAIN world への注入と Canvas API の互換性は検証できますが、Google Sheets 自体の DOM 変更、ログイン、実編集、数式・条件付き書式は保証しません。実サービスの確認は `pnpm verify:sites` で分けています。

## トランジションと配色の独立性

[transitions.spec.ts](../tests/browser/transitions.spec.ts) は、配色の適用だけでサイト側の操作完了通知が出ないことを、通常 DOM と Shadow DOM で確認します。実装の再走査回数や CSS の書式は判定に使いません。利用者が透明度を変えるボタンを押した後は、CSS の遷移が完了し、サイトの `transitionend` リスナーから操作完了を表示することも確認します。色の自己ループを止めるために、無関係な遷移まで壊してしまう修正を検知するためです。元の inline `!important` の文字色を変え、遷移中に別の DOM 更新が起きても、その色の遷移とサイト側の完了通知が保たれることも確認します。

2026-11-08 に基準コミット `a5c9f8f` でこのテストを実行し、操作前の『操作待ち』が『未操作の色変更』になるアサーション失敗を確認しました。修正後は同じテストが通っています。既存の Animation オブジェクトとの比較だけにした中間コミット `a803b98` では、元の文字色の遷移を保護する追加ケースが、完了通知の欠落を検知しました。`4f2026a` の修正後は追加ケースも通っています。

同じテストファイルで、元が同色の面の片方だけを変更しても、隣の面・異なる色の疑似要素が変色しないことと、変更を戻したときに元へ戻ることを確認します。CSS ルールの共有で別要素の色を巻き込む不具合や、疑似要素の差を落とす不具合を検知します。

色の遷移を一時停止してからキャンセルし、その後に追加された白い面が暗く読みやすい状態になることも確認します。遷移の中断で待機状態が解除されず、後続の DOM 更新を処理できなくなる不具合を検知するためです。

負荷の改善は、固定した関数の呼び出し回数や環境依存の実行時間だけを合否にせず、[比較スクリプトの実測](performance/2026-11-08-improvement/README.md) で確認します。

## 削除・置き換えた判定

2026-11-06 の見直しで、次の判定を削除・置き換えました。本番の色変換・設定処理は変更していません。

| 以前の判定                                                         | 判断と変更後                                                                      |
| ------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 白の変換結果が RGB の固定値になる                                  | 固定値の確認を削除。暗さ・可読性・色の区別で判定                                  |
| `serializeColor` の出力文字列が `rgba(...)` と一致する             | 単体テストを削除。ブラウザが解釈し、期待する表示になるかで判定                    |
| `composite` に半透明の白を渡すと数値が `127.5` になる              | 算術ヘルパーの単独テストを削除。表示色を独立した式で合成して可読性を判定          |
| 色パーサーを Map で差し替え、複合 CSS の変換結果の文字列を比較する | モックを使う単体テストを削除。実ブラウザで色形式・グラデーション・画像 URL を確認 |
| 本番の `contrast` で、本番の文字変換を採点する                     | 独立した WCAG の判定へ置換                                                        |
| 元の白以外の色になれば合格                                         | 暗い背景と読める文字の両方を判定。変更の前後も比較                                |
| 画像自身の `filter` が `none` なら合格                             | 画面に描かれた色へ置換。祖先の反転も検知                                          |
| Canvas API を呼び、最後に `restore()` した色だけ確認する           | 各メソッドの実描画と、呼び出し直後の状態を確認                                    |
| 拡張固有の DOM 属性や元の inline style 文字列の一致                | 内部属性の確認を削除。表示・設定の永続化・後続更新の結果を確認                    |
| ドメイン一覧が特定の並び順で返る                                   | 並び順の固定を削除。除外対象の集合と重複除去を確認                                |
| 公開 Sheets で操作を送ったら `selectionAndScroll: true` と記録する | 固定の成功値を削除。選択セルと Canvas の描画内容の変化を確認                      |

スクリーンショットの保存だけを合否判定に使うテストは追加していません。画像は検証記録・調査用で、合否は上記の性質や実操作の結果から判定します。

## 不具合を入れたコピーでの検知確認

2026-11-06 に一時ディレクトリへコードとテストをコピーし、正常な状態で単体テスト・ビルド・E2E が通ることを確認しました。そのコピーだけを 1 箇所ずつ壊し、次の 11 種類すべてでテストのアサーションが失敗することを確認しました。コンパイル失敗だけを検知成功には数えていません。

| 入れた不具合                                 | 検知したテスト                                               |
| -------------------------------------------- | ------------------------------------------------------------ |
| 本番のコントラスト判定が常に合格             | 独立した WCAG による本文色の単体テスト                       |
| ドメイン境界のドットを無視                   | `notexample.com` / `otherexample.com` を除外しない単体テスト |
| ページの祖先へ `invert(1)` を適用            | 画面上の画像の色を比較するブラウザテスト                     |
| DOM の変更監視を無効化                       | 非同期の要素追加・inline style 更新のブラウザテスト          |
| CSSOM の確認が検証時間内に動かない           | CSSOM 更新のブラウザテスト                                   |
| Canvas の文字を背景と同じ色で描く            | 文字のピクセルを確認するブラウザテスト                       |
| Canvas の元の `fill` を呼ばない              | 塗りつぶし領域のピクセルを確認するブラウザテスト             |
| Canvas の `fillStyle` を呼び出し後に戻さない | API 呼び出し直後の状態を確認するブラウザテスト               |
| Canvas がドメイン除外を無視                  | Sheets の除外・解除のブラウザテスト                          |
| 設定画面の保存が一覧を保持しない             | 設定の再表示と実ページへの反映のブラウザテスト               |

[検知結果の JSON](test-sensitivity.json) に、対象ソースの SHA-256、入れた変更、失敗したテスト名を残しています。この結果は選んだ 11 種類への検知力を示すもので、全種類の不具合を検知するという意味ではありません。テスト数や通過率だけを品質の根拠にはしません。

## 実行

```sh
pnpm check
pnpm test:e2e
pnpm verify:sites
```

ブラウザテストの確認画面は、`node tests/server.mjs` を起動して [通常ページ](http://127.0.0.1:4173/) と [CSP のページ](http://127.0.0.1:4173/strict.html)、[トランジションのページ](http://127.0.0.1:4173/transitions.html) から開けます。サーバー停止中はアクセスできません。Sheets の制御ページはテストがルーティングする URL のため、同じ URL を普段の Chrome で開いても検証用 HTML は表示されません。
